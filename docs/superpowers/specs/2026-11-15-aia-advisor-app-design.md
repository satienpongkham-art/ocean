# AIA Advisor App (แอปส่วนตัวของตัวแทน) — Design

วันที่: 15 พ.ย. 2569 · ผู้ใช้: เสฐียรพงษ์ คำศรี (Financial Advisor, AIA, รหัสตัวแทน 731462)

## เจตนา / Why
ตัวแทนไม่มีเวลาศึกษาแผนทั้งหมด ต้องการระบบของตัวเองที่ "กดแล้วเข้าใจแผนทันที" (คืออะไร ดียังไง เหมาะกับใคร ข้อควรรู้)
จับคู่เป็นแพ็กเกจ 3 ระดับ แนะนำลูกค้าตามสถานการณ์พร้อมเหตุผล และเป็นระบบทำงานประจำวันของตัวแทน (นัด/รายชื่อ/แมนฮาร่า)
ข้อมูลเป็นของผู้ใช้เอง ใช้คนเดียว ทั้งมือถือและคอม ข้อมูลตรงกัน

## เป้าหมาย
1. คลังแผน AIA (ช่องทางตัวแทน ไม่รวมยูนิตลิงก์) ข้อมูลตรงตาม aia.co.th + โบรชัวร์ พร้อมการ์ดป๊อปอัป: สรุป 1 ประโยค · เหมาะกับใคร · จุดเด่น · ทำไมดี · ข้อควรรู้ · เงื่อนไข · ตารางผลประโยชน์ · กราฟระยะจ่าย/คุ้มครอง · ตัวอย่างเบี้ยจากโบรชัวร์ · ปุ่มลิงก์หน้า AIA/โบรชัวร์
2. แพ็กเกจ 3 ระดับ (พื้นฐาน / กลาง / เต็มแม็กซ์) หลายชุดตามเป้าหมาย พร้อมเหตุผลการจับคู่
3. ระบบแนะนำ (กฎ ไม่ใช้ AI ภายนอก): ใส่อายุ รายได้ สถานะ ภาระ สวัสดิการ → แพ็กเกจ + ประโยคอธิบาย "ทำไม" + case study ตามช่วงวัย
4. ลูกค้า (ชื่อเล่น): โปรไฟล์ 360, Financial Health Check, แมนฮาร่า 8 ด้าน (ชีวิต สุขภาพ โรคร้ายแรง อุบัติเหตุ ออม เกษียณ การศึกษาบุตร ภาษี)
5. ระบบงานตัวแทน: รายชื่อ 100 + เกรด A/B/C, ท่อการขาย (รายชื่อ→นัด→พบ→เสนอ→ปิด→ส่งมอบ), โหมดโทรนัด, โค้ชวันนี้, ปฏิทินวันเกิด, ตัวคำนวณย้อนจากเป้า, ทบทวนสัปดาห์, สายรายชื่อแนะนำ, แมนฮาร่าเป้าหมายตัวแทน
6. เครื่องมือ: คำนวณลดหย่อนภาษี (มีชุดทดสอบ), การ์ดรับมือข้อโต้แย้ง, ตัวสร้างแคปชั่น FB/IG/TikTok (ตามกฎ คปภ.)
7. โปรไฟล์ตัวแทน (เลขใบอนุญาตเว้นไว้กรอกเอง)

## ไม่ทำ (Non-goals)
- AI/LLM ภายนอก, การดึงโพสต์โซเชียลเรียลไทม์, อัปเดตแผนอัตโนมัติ
- ใบเสนอเบี้ยแม่นทุกอายุ (ใช้ตัวอย่างจากโบรชัวร์ + ตารางเบี้ย PA จริง + ช่องกรอกเบี้ยจริงจากระบบ AIA)
- ยูนิตลิงก์ (รอใบอนุญาต IC) · ทบทวนกรมธรรม์ปีละครั้ง (เลื่อนไปก่อน)
- รูปโปสเตอร์ของ AIA (ใช้ลิงก์ไปหน้าเว็บ AIA แทน)

## Anti-goals
- ข้อมูลแผนผิด/แต่งขึ้น — ทุกตัวเลขต้องมีที่มา ถ้าไม่ใช่การันตีต้องระบุ
- หน้าตา "เหมือน AI ทำ" (ไล่สีม่วง, emoji รก, การ์ดกระจก)
- ข้อความโฆษณาผิดกฎ คปภ. (การันตีผลตอบแทนที่ไม่การันตี, เปรียบเทียบเกินจริง)

## ข้อจำกัด
- โฮสต์ฟรี GitHub Pages (repo `ocean`, สาธารณะ) → ห้ามมีข้อมูลลูกค้าใน repo
- ข้อมูลลูกค้าเก็บในเครื่อง (localStorage) + ซิงก์ผ่าน Google Sheets ของผู้ใช้ (Apps Script Web App)
- ไม่มีขั้นตอน build · ใช้มือถือเป็นหลัก ใช้คอมได้ · ติดตั้งเป็นแอป (PWA) ใช้ออฟไลน์ได้

## Approaches (ที่พิจารณา)
- **A. หลายไฟล์ ES modules ไม่ต้อง build (เลือก)** — ข้อมูลแผนแยกไฟล์ `data/plans-*.js` ผู้ใช้แก้เองบน GitHub ได้, ไม่มี build ที่พัง
- B. React + build pipeline — โครงสร้างดี แต่แก้ข้อมูลยาก ต้องรอ build
- C. HTML ไฟล์เดียว — ยาวหลายหมื่นบรรทัด แก้ยาก เสี่ยงพัง (ตัดทิ้ง)

ซิงก์: A. Google Sheets + Apps Script (เลือก — ข้อมูลอยู่ใน Drive ผู้ใช้, ฟรี) · B. Firebase (เร็วกว่า แต่ตั้งค่ายาก ข้อมูลดูยาก)

## การออกแบบ
- โครงไฟล์: `index.html` (app shell) · `css/app.css` · `js/app.js` (router hash) · `js/store.js` (localStorage + sync) · `js/views/*` · `js/engine/*` (recommend, tax, goals, coach) · `data/*` · `apps-script/Code.gs` · `sw.js` + `manifest.webmanifest`
- หมวดเมนู (ล่างจอบนมือถือ / ซ้ายบนคอม): วันนี้ · แผนประกัน · ลูกค้า · งานขาย · เครื่องมือ
- ดีไซน์: โทนกระดาษอุ่น + เขียวหมึกเข้ม + แดง AIA เป็นจุดเน้นเล็กน้อย, ฟอนต์ IBM Plex Sans Thai (เนื้อหา) + IBM Plex Sans Thai Looped/ตัวเลข tabular, เส้นบาง ไม่ใช้ไล่สี ไม่ใช้ emoji เป็นไอคอน (ใช้ SVG เส้น)
- ซิงก์: เก็บทุกคอลเลกชันเป็น JSON ต่อแถว (id, collection, updatedAt, data) ใน Sheet; รวมข้อมูลด้วย updatedAt ล่าสุดชนะ, ลบแบบ tombstone
- Health Happy: ป้ายนับถอยหลังถึง `closing` (30 พ.ย. 2569) แก้ได้ในไฟล์ข้อมูล

## ปล่อยให้ผู้สร้างตัดสินใจ
รายละเอียดเลย์เอาต์ ข้อความ UI กฎตัวเลขในระบบแนะนำ (อิงหลักการวางแผนการเงิน: ทุนชีวิต 5–10 เท่ารายได้ต่อปี + หนี้, งบเบี้ย 10–15% ของรายได้, ค่ารักษาโรคร้ายแรง) โดยระบุที่มา/สมมติฐานในแอป
